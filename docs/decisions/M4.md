**Decision (frozen).** Default scorer: **fine-tuned ESM-C k=3 (seed 0) suffix +
linear head D=128, residue rows L2-normalized, raw (unnormalized) MaxSim sum,
chunking WIN=2046 / OVERLAP=128** — beats mmseqs2 on cR@10 (+0.067),
sens_family (+0.049), sens_superfamily (+0.128) on the deployment-shaped
corpus. Everything after this point uses it unchanged. Length normalization:
none (raw).

**Why / notes.** Length bias is mild for all scorers at this scale (ρ ≤ 0.17);
the trained scorer is *most* length-correlated yet best-ranking — ρ alone does
not predict retrieval quality. Prefix inputs for the trained scorer must come
from the HF path (esmc.cpp applies `output_norm` unconditionally, plan M3
cached-prefix layout is pre-norm). MPS `Tensor.scatter_reduce` (no underscore)
returns a new tensor and in-place calls on broadcast views are silent no-ops —
segment-max now runs on CPU via `np.maximum.reduceat` threads overlapped with
GPU GEMMs (validated vs GPU scatter: max rel diff 1e-6, ~2.2× faster, and it
keeps the GPU out of thermal creep). Two silent process kills during long runs
were system-memory pressure, not bugs: `get_matrix` caches + per-block
progress make every stage resumable; `CHUNK_QUERIES=4` caps host buffers.
Baseline order at scale: trained > mmseqs2 > maxsim960 > maxsim128 > pooled >
minhash >> random.
