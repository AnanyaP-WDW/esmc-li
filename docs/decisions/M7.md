# Gate M7 — decision

**Result.** T7.1 (`results/m7_compression.csv`): `residual_pq_m32` is the
only scheme meeting the exit (7.76x smaller; cR@10 0.8921 vs 0.8974, drop
0.0052). int8/residual_int8 are only 2x; residual_pq_m16/m8 drop
0.0158/0.0461. T7.2 (`results/m7_scaling.csv`): candidate recall 0.994 at
C=30K on 1M (0.996 @ C=10K on 100K, 0.994 @ C=3K on 10K); rerank top-10
agreement vs exhaustive is 0.94/0.98/0.94. 1M exhaustive is 11.13 s/q vs
coarse 10.26 s/q -> only 1.1x (10K/100K were 1.1/2.6); the rerank alone is
9.86 s/q because candidate docs are randomly gathered from the 81 GB index.
T7.3:
10K 629 s / 0.807 GB; 100K 6,434 s / 8.14 GB; 1M 62,947 s / 81.17 GB;
open 6-8 ms; exhaustive 0.112/1.15/11.13 s/q.

**Decision.** PASS with a systems caveat: keep f16 `.esmci` + exhaustive
fused-metal search as the default. Do not ship the compressed payload or the
coarse stage at 1M: recall passes, but random candidate gather makes rerank
nearly as expensive as exhaustive (9.86 vs 11.13 s/q), so V3 buys only 1.1x.
10M is deferred: ~7.3 days build and ~810 GB index on this machine; it needs
external storage and a candidate-aware layout before V3. Revisit `m32` only
alongside a fused decode+MaxSim kernel.
