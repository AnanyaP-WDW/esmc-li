# M8 — package and CLI

**Result.** `ProteinIndex` (`from_fasta/build/load/search/search_batch`) and
`esmc-retrieval build/search/benchmark` ship. Query rows use esmc.cpp
`--keep-special` (commit `218cc69` or later) + the packaged 960->128 head;
index rows retain BOS/EOS to match the frozen scorer. Exact search is numpy
with an optional fused Metal backend (`device="auto"`); no torch dependency.
The index sidecar records head/model hashes and the head is copied to
`<index>.head.npy`. Wheel contains the head and target-install search works.
Tests: 40 pass; 1K SCOPe smoke is 10/10 top-1 same superfamily (8/10 same
family; 23.2 s build+search, 50 MB index); long >2046 chunking covered.

**Published.** Model `esmc-300m-homology-maxsim-v1` (GGUF + head) and dataset
`esmc-retrieval-indexes` (`scope-1k`, `swissprot-100k`). Profile (M4 Max):
1K encode 61 ms / search 19 ms per query; 100K encode 113 ms / search 1.29 s
per query with Metal; numpy fallback is ~9 s/query. Single-query `search()`
is ~0.6 s (1K) / ~2.8 s (100K) because it includes model load.

**Decision.** Ship the package/CLI as v0. Query encoding stays CLI-based
(model load per single query; `search_batch` uses one process); add a shared
library bridge only if measured query latency requires it. Use Metal on macOS
when available, numpy otherwise. Index build uses `--keep-special`, not the old
stripping path. Q4 GGUFs warn. Indexes remain a separate optional artifact;
the index is not self-contained without its head/model.
