# M8 — package and CLI

**Result.** `ProteinIndex` (`from_fasta/build/load/search/search_batch`) and
`esmc-li build/search/benchmark` ship. Query/build use the in-process
`libesmc` C API via ctypes (persistent `esmc_model`/`esmc_context`) plus the
packaged 960->128 head; index rows retain BOS/EOS to match the frozen scorer.
Source installs fall back to the `--keep-special` CLI. Exact search is numpy
with an optional fused Metal backend (`device="auto"`); no torch dependency.
The index sidecar records head/model hashes and the head is copied to
`<index>.head.npy`. Wheel contains `libesmc` + ggml dylibs, the head, and a
platform tag; target-install search works. Tests: 43 pass; 1K SCOPe smoke is
10/10 top-1 same superfamily (8/10 same family; 23.2 s CLI build+search,
50 MB index); long >2046 chunking covered.

**Published.** Model `esmc-li-300m-v1` (renamed from
`esmc-300m-homology-maxsim-v1`) and dataset `esmc-li-indexes` (renamed from
`esmc-retrieval-indexes`); `scope-1k`, `swissprot-100k`. Model/head/index
downloads are cached by `huggingface_hub`; `index pull scope-1k` works.
Profile (M4 Max, Metal search): 1K encode 61 ms / search 19 ms per query;
100K encode 113 ms / search 1.29 s per query; numpy fallback is ~9 s/query.
The runtime removes per-query model load; the first model/context load is
~0.6 s (after Metal cache warm).

**Decision.** Ship the package/CLI as v0. Use `libesmc` in-process on macOS
arm64/Linux x86_64 wheels; keep the CLI only as source/unsupported-platform
fallback. Use Metal search when available, numpy otherwise. Model and
prebuilt indexes download from HF and verify SHA256. macOS binaries are
unsigned; print a warning. Q4 GGUFs warn. Indexes are separate artifacts and
are not self-contained without their head/model.
