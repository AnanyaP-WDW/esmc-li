## ERAST and maxsim-rs resolution

**ERAST — RESOLVED, keep it (drop the UNVERIFIED flag).**
Primary source: "Scalable homology detection with ERAST", Nature Biotechnology, published 1 April 2026, DOI [10.1038/s41587-026-03051-1](https://www.nature.com/articles/s41587-026-03051-1) (PubMed 41922694). Authors: Yinuo Jiang, Bing He, Jianhua Yao et al. (Tencent AI Lab). The plan's claim — "reported Nat Biotech 2026, billion-scale protein retrieval" — matches: the paper targets ~1 billion biological sequences in "the largest vector database to date", ~50× faster than Foldseek, ~50,000× faster than TM-align. Code: https://github.com/TencentAILabHealthcare/ERAST. Caveat: it is a vector-DB/LLM hybrid system (not a PLM retriever trained with contrastive learning), so in §15 it belongs under dense/system baselines, and reproduction may depend on their hosted DB.

**maxsim-rs — DOES NOT EXIST AS A PUBLISHED CRATE; recommend deletion (or swap in a real crate).**
Searched crates.io API (`q=maxsim`, `q=colbert`) plus direct lookup: `maxsim-rs` → 404, `maxsim` → 404. The only match anywhere is a GitHub repo, https://github.com/maxbaluev/maxsim-rs (created 10 Jun 2026, 1 commit, 0 stars, MIT, never released to crates.io) — not a citable engineering baseline. Recommendation: delete `maxsim-rs` from §9 and T5.4. Real crates.io alternatives to price instead: [`next-plaid`](https://crates.io/crates/next-plaid) (lightonai, CPU PLAID multi-vector search), [`ruvector-maxsim`](https://crates.io/crates/ruvector-maxsim), [`rank-refine`](https://crates.io/crates/rank-refine), [`innr`](https://crates.io/crates/innr) — all found via the crates.io search API.
